# Z-RIDE 장소별 게임과 Pleos 차량 화면

2026-11-08 KST

## Pleos 내비와 차량 신호 연결

- 승인된 동승자의 폰은 차량 주변 위치도를 먼저 보여 준다. 지도에서 보급 스팟, 충전소, DEADZONE 집결지를 선택하면 가능한 활동이 표시된다. 미니게임 화면의 돌아가기 버튼으로 파티를 유지한 채 지도로 돌아간다.

- AAOS `PERF_VEHICLE_SPEED`는 승인된 파티에 m/s 단위로 전달한다. 수집 화면은 km/h로 표시하며 차량 연결이나 최신 측정값이 없으면 속도를 표시하지 않는다. 차량 속도는 동승자 화면 연출의 입력이다. 정차 게임의 `virtualSpeedMps`는 실내 풍량 연출에 사용하는 별도 값이다.

- NaviHelper가 안내 중인 목적지와 최신 차량 위치를 보고하고 차량이 D이면, 서버가 기존 장소 목록에서 180m 안의 미수집 스팟을 찾아 승인된 동승자에게 수집 버튼을 표시한다. SDK가 도로 경로 형상을 제공하지 않아 Pleos 안내 중에는 실제 차량 위치 기준으로 판정한다. 외부 도로 경로를 명시한 경우에만 경로 회랑을 추가로 검사한다.
- 검증된 충전소 구역에서 차량의 기어가 P이고 플러그 연결과 충전이 확인되면 전기도둑과 충전 릴레이가 열린다. 차량 화면에서 게임을 선택하면 참가 중인 동승자의 폰에 표시된다.
- DEADZONE 웨이브 클리어는 별도의 차량 라운드를 시작하지 않아도 조명을 요청할 수 있다. 앱을 연 주차 상태와 차량 화면의 앰비언트 동의가 필요하다.
- LAN 검증 서버를 `ZRIDE_NATIVE_VEHICLE=1`로 시작하면 내비와 차량 신호를 중계 과정에서 바꾸지 않는다. 장소 검증은 일반 서버의 운영 승인과 별도로 이 LAN 시연 인스턴스에서만 적용한다.

## 이동 중 빗방울과 경로 보상

- 속도는 차량에서 읽은 최신 값을 km/h로 정규화한다. 빗방울 생성률과 이동 속도는 별도로 계산한다. 빠를 때 더 빨리 흘러가게 하되, 상한을 두어 난이도가 지나치게 뛰지 않게 한다. 속도가 없거나 오래된 경우 연습 상태로 전환하고 경로 보상을 지급하지 않는다.
- 터널은 도로에 매칭된 차량 위치와 지도/경로 구간 속성을 사용해 OUTSIDE, INSIDE, UNKNOWN으로 구분한다. GNSS가 잠시 끊겨도 바로 터널로 판정하지 않는다. INSIDE에서는 새 물방울과 새 물보라 생성을 멈추고 이미 생성된 물방울은 계속 움직인다. 출구에서 밀린 물방울을 한꺼번에 생성하지 않는다. 기존 무작위 터널은 연습 모드에 한정한다.
- 차량이 경로상의 아이템 구간을 통과하면 서버가 파티와 경로 버전, 구간 ID를 묶어 획득 기회를 만든다. 새로고침이나 재연결에도 같은 기회는 중복 정산하지 않는다. 폰에는 승인된 좌석, 현재 구간, 유효한 속도와 아이템 기회만 보내는 것을 기본으로 한다.
- 현재 앱의 VehicleProbe는 기어·충전 등 기존 속성을 읽고, NavigationProbe는 위치·방향을 받는다. 실차 속도 수신과 터널 구간 판정은 다음 검증 항목이다. 기존 게임의 가상 속도는 별도 값으로 유지한다. [AAOS 차량 속성](https://developer.android.com/reference/android/car/VehiclePropertyIds)

## DEADZONE 공유 차량

기존 각 캐릭터의 자유 이동을 공유 차량으로 바꾸려면 게임 서버의 시뮬레이션부터 바꿔야 한다. 모든 클라이언트가 같은 차량 스냅샷을 받고, 카메라와 총구 위치는 차량 위치에 좌석 오프셋을 더해 구한다. 첫 버전은 차량이 정해진 경로를 따라 이동하고 폰에서 좌석별 조준·사격만 받는다. 피격과 체력은 차량 한 대 기준으로 합산한다. 나중에 차량을 조종하는 역할을 추가할 수 있다.

실제 P·UX 신호는 전투를 열거나 닫는 데 쓰고, 게임 속 차량 이동에는 가상 속도를 사용한다. 실제 도로 주행 중에는 전투용 화면과 조명 효과를 중단한다. 웨이브 클리어는 게임 서버에서 확정한 이벤트 ID로 한 번만 전달한다. 기존 조명 적용·원복과 함께 D 전환·재접속·중복 이벤트도 검증한다. [Pleos 주행 제한](https://document.pleos.ai/en/docs/pleos-only/distribute/app-review-guide/review-driver-distraction-elements)

## 센터 화면

- 앱에 할당된 창을 기준으로 배치한다. Pleos 상하단 시스템 바와 분할 창 영역을 뺀 공간에서 확인한다. 넓은 대기실은 왼쪽 QR과 오른쪽 파티원/승인, 좁은 창은 세로 배치다. 서버 주소와 센서 원문은 진단 모드로 유지한다.
- 충전소에서는 현재 충전 상태와 선택한 게임의 시작 조건을 한 화면에 표시한다. 게임 진행 중에는 차례, 공동 목표, 남은 시간 중 해당 게임에 필요한 정보만 표시한다.
- 이동 중 놀이터의 플레이·보상은 승인된 동승자 폰에서 진행한다. 차량 화면에는 게임 조작이나 순위를 띄우지 않는다. 정차 후에는 수집 결과를 볼 수 있다.
- DEADZONE 경기 화면은 공동 차량 체력, 웨이브, 팀 점수, 파티 순위 중심으로 구성한다. 대기실에 표시되는 QR과 참가 승인 영역은 경기 진행 중 접는다.

이번 작업은 데모 코드 조사, 연동 설계, Pleos 대기실 배치 조정까지다. 각 데모의 게임 로직과 서버 계약은 이후 실제 소스에서 수정하고 검증해야 한다.

## 지도 스팟과 이동 중 아이템 사용 검토

- **방문 스팟**은 충전소·휴게소처럼 차를 세워 게임을 여는 장소다. 기존 경로 검색은 검증된 진입점과 주차·체류 조건을 사용한다. 경로 근처에 있다는 사실은 후보 표시로 쓰고, 게임 시작은 해당 장소 도착과 주차 상태를 확인한 뒤 제안한다. 충전 게임은 충전 상태도 확인한다.
- **수집 구간**은 예정 경로를 정상적으로 통과하면 동승자 폰에 짧은 수집 기회가 생기는 구간이다. 승인된 동승자 한 명이 미니게임을 완료하면 파티 보급품을 적립한다. 여러 폰에서 동시에 완료하거나 재접속해도 같은 기회는 한 번만 정산한다. 우회나 정차를 유도하지 않는다. 기존 서버에는 위치 검증과 파티 단위 중복 수집 방지가 있지만, 차량의 경로 구간 통과로 기회를 여는 기능은 별도 구현이다.
- 지도에는 방문 스팟과 수집 구간을 서로 다른 표식으로 표시한다. 운전자 화면은 목적지와 경로를 유지하고, 폰에서 수집 기회·남은 시간·적립 결과를 보여준다. 경로가 바뀌면 아직 지나지 않은 수집 기회만 새 경로에 맞춰 갱신한다.

| 게임 | 이동 중에 모은 보급품의 사용 |
| --- | --- |
| DEADZONE | 첫 연동 대상으로 적합하다. 웨이브 사이에 보급품 1개로 공유 차량을 한 번 수리한다. 기존 Z-RIDE 서버에는 보급품 1개를 차감하는 지원 동작이 있으므로 재고는 재사용한다. DEADZONE 수리 적용과 차감은 경기 ID·웨이브에 묶고 적용 확인 후 확정한다. |
| 전기도둑 | 이후 파티 공동 비상 퓨즈를 한 번 보충하는 식으로 연결할 수 있다. 실제 SOC, 비밀 역할, 승패 조건과 팀 순위 점수는 보급품으로 바꾸지 않는다. |
| 충전 릴레이 | 여행 보상으로 테마나 결과 카드 꾸미기를 연다. 전달 성공률이나 투표 점수에는 영향을 주지 않는다. |
| Z-RIDE 놀이터 | 빗방울 캐치 등의 기록을 경기 결과로 남기고, 해당 수집 기회의 완료를 파티 보급품으로 변환한다. 웹 게임의 로컬 아이템 수량을 서버 재고로 그대로 인정하지 않는다. |

첫 시연은 아이템 종류를 **파티 보급품 한 종류**로 제한한다. 예를 들어 충전소로 가는 동안 동승자가 빗방울 캐치를 완료하면 보급품 1개가 쌓이고, 나중에 주차한 뒤 DEADZONE의 웨이브 사이에 차량을 수리할 수 있다. 보급품이 없어도 게임 기본 진행은 가능하다. 팀 비교 기록에서는 아이템 사용 여부를 남기고, 보급품 보조를 받은 경기와 기본 조건 경기를 같은 순위에 넣지 않는다.

## 한 번 가입하는 여행 검증

- 운전자 민준이 Pleos에서 파티를 만든다. 조수석 지우, 뒷좌석 왼쪽 하린, 뒷좌석 오른쪽 서준이 같은 QR로 참가하고 승인받는다.
- 이동 중 두 경로 스팟에서 동승자 폰이 숫자 기억 미니게임을 연다. 스팟마다 파티 보급품 하나를 적립한다.
- 지도에서 검토가 완료된 충전소의 게임 구역에 도착해 주차하고 충전 중일 때 Pleos에서 전기도둑이나 충전 릴레이를 연다. 세 폰은 기존 파티 연결과 좌석을 유지한다. 전기도둑은 SOC가 5% 오르면 사건을 시작하고, 보급품 하나로 정전 기록을 한 번 복구할 수 있다. 충전 릴레이에서는 보급품 하나로 해당 라운드의 현재 입력 시간을 15초 늘린다.
- 충전 게임을 끝내고 주차 중 DEADZONE을 열면 같은 세 폰에 좌석별 입장 링크가 뜬다. 게임 서버는 승인된 좌석 티켓을 확인한다. 공유 차량은 자동으로 이동하고, 사격은 각 좌석의 허용 방향에서만 실행된다.

전기도둑은 GitHub `feat/pleos-game-hub`의 `3a5b3c0` 서버 상태 기계를 재사용한다. 손패의 합을 사건마다 제시되는 범위에 맞추고, 범위 미달은 정전, 초과는 과부하로 처리한다. 동승자 두 명이면 차량이 숨은 값을 더하고, 세 명 이상이면 도둑 역할과 투표가 열린다. 기존 QR 파티의 보급품 하나로 실패한 사건을 한 번 복구할 수 있다. 충전 릴레이의 엔진은 같은 커밋과 동일하다. 충전 게임의 진행은 서버 메모리에 있다. 전기도둑의 실내 효과는 게임 상태에 반영되며, 이 통합 경로의 실제 공조 및 조명 실행은 별도 검증이 필요하다. [게임 업데이트](https://github.com/HeIIowrld/z-ride/commit/3a5b3c0)

자동화 재현은 로컬 DEADZONE Worker를 실행한 상태에서 Z-RIDE 저장소 루트에서 `DEADZONE_ROOT`와 `DEADZONE_ORIGIN`을 설정하고 `node server/tools/venue-journey-live.mjs`를 실행한다. Git 장소 목록을 읽고 시험 서버 안에서만 충전소 하나의 도착 조건을 등록한다. 같은 세 동승자가 수집, 두 충전 게임, 아이템 사용, DEADZONE 입장과 좌석 방향별 사격을 검증한다.


Pleos 차량 1에서 실제 앱의 전기도둑·충전 릴레이 선택, 시작, 두 보급품 사용과 DEADZONE 방 열기를 눌렀다. 같은 파티의 자동화 폰 세 개가 두 게임의 입력과 결과를 완료하고 DEADZONE에서 각 좌석의 허용 방향으로 사격했다. 승인 티켓 없는 입장과 좌석 방향 밖 사격은 차단됐다. 시험용 프록시가 충전·SOC·기어·위치 신호를 공급했으며, 실물 폰과 실제 차량 신호는 별도 검증이 필요하다. 앱에서 충전 게임 중 기존 라운드 버튼을 숨기는 화면 정리는 이 시험 뒤 빌드에 반영했다.
