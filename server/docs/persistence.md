# SQLite 영속화 — 방·인벤토리·중복 지급 기록

2026-11-01. 서버를 다시 시작해도 같은 방과 공동 인벤토리를 복원한다. 단일 Node 프로세스·SQLite 파일·지속 볼륨을 사용하는 현재 데모 구조다. DB 파일이 없는 예전 메모리 서버의 이미 실행 중인 방을 자동 이관하는 기능은 포함하지 않는다.

## 실행

CLI `node server.mjs`는 작업 디렉터리의 `data/zride.sqlite`를 기본으로 사용한다. 배포 환경은 `ZRIDE_DB_PATH=/data/zride.sqlite`를 설정하고 **디렉터리 `/data` 전체를 지속 볼륨**으로 연결한다. Node.js 최소 버전은 22.13.0이다.

프로그램에서 만드는 `createDemoServer()`는 기존 시험과 호환되게 메모리 상태를 쓴다. 파일 저장이 필요하면 `createDemoServer({dbPath:'/data/zride.sqlite'})`를 사용한다. 따라서 서버 시험마다 실사용 DB를 덮어쓰지 않는다. [`node:sqlite` 22.13 공식 명세](https://github.com/nodejs/node/blob/v22.13.0/doc/api/sqlite.md)

## 저장하는 데이터

| 데이터 | 재시작 처리 |
| --- | --- |
| 세션 ID·역할·닉네임·만료 시각·방 연결 | 같은 기존 토큰으로 재인증 가능. 원래 8시간 만료는 연장하지 않음 |
| 토큰 | SHA256 조회 키만 DB에 저장. 원문 토큰은 최초 발급 응답으로만 전달 |
| 방 ID·좌석·멤버 승인·게임 진행 | 같은 ID와 역할·승인 상태 복원 |
| 공동 인벤토리·좀비 HP·통계 | 마지막 성공 명령의 확정 상태 복원 |
| fixture·world 획득 원장 | 같은 스폰·일정의 재획득 방지 유지 |
| WS/world 명령 영수증 | 성공 여부가 불명확한 기존 명령 재전송 때 중복 효과 방지 |
| 유효한 미사용 참가 코드 | 원래 유효기간 안에서만 유지 |

원시 폰 좌표·전체 이동 경로·30초 위치 품질 요약은 저장하지 않는다. world 명령은 본문 해시와 결과만 보관한다. 다만 멤버별 스폰·일정 기록은 방문을 추론할 수 있는 자료이므로 서비스 보존·삭제 정책이 여전히 필요하다.

## 원자성과 응답 순서

`server_state`의 한 행에 `format_version`, `revision`, JSON `payload`, `saved_at`을 저장한다. 방·재고·획득 여부·명령 영수증이 한 checkpoint에 함께 들어간다.

1. HTTP 본문 읽기는 먼저 완료하고, 메모리 상태를 바꾸는 작업은 동기 transaction 경계 안에서 수행한다.
2. 명령 효과와 영수증을 모두 만든다. 성공 응답과 snapshot 방송은 잠시 보류한다.
3. SQLite `BEGIN IMMEDIATE` → checkpoint 갱신 → `COMMIT`을 수행한다.
4. 커밋이 성공한 뒤 응답·ACK·WebSocket snapshot을 전달한다.

SQLite는 WAL·`synchronous=FULL`·5초 busy timeout을 쓴다. revision 비교는 별도 서버가 낡은 checkpoint를 덮어쓰는 일을 막는다. **여러 서버가 같은 파일을 공유하는 클러스터 구조는 지원하지 않으므로 인스턴스는 하나만 실행한다.**

매번 전체 checkpoint를 직렬화하는 방식은 현재 소규모 데모의 원자성을 단순하게 만든다. 대규모 동시 방·장기 영수증·다중 인스턴스가 필요하면 정규화된 DB와 트랜잭션/원장 구조로 분리해야 한다.

## 안전한 복원과 저장 실패

재시작 시 실제 소켓 연결은 모두 null이다. 차량 UX·기어는 UNKNOWN, foreground=false, heartbeat 시각은 0으로 초기화한다. PLAYING이었던 방은 PAUSED로 바꾸고 전투 epoch를 올린다. 일시 지원 효과도 끝낸다. 인벤토리에서 이미 소비한 지원 재료를 반환하거나 다시 소비하지 않는다.

클라이언트는 기존 token·roomId로 새 WebSocket을 인증한다. 차량은 **현재 신호를 새 commandId로 보고**하고 운전자가 명시적으로 전투를 재개한다. 과거 vehicle.report 성공 영수증을 재전송하는 것만으로 새 차량 허용 조건이 생성되지 않는다.

DB 쓰기가 실패하면 성공 응답·갱신 방송을 보내지 않고 소켓을 닫는다. 해당 서버 인스턴스는 `STORAGE_UNAVAILABLE` 503과 실패 health를 반환하며 DB 접근을 복구한 뒤 재시작해야 한다. 마지막 커밋을 읽으므로 실패한 보상은 다음 재시작에서 나타나지 않는다. 오류를 무시하고 메모리 전용으로 계속 보상을 지급하지 않는다.

## 파일·백업

파일과 WAL/SHM 파일은 0600 권한으로 만들며 새 상위 디렉터리는 0700을 요청한다. 배포 볼륨은 Node 사용자(uid 1000)가 쓸 수 있게 설정한다. DB·`-wal`·`-shm` 파일을 Git에 넣지 않는다.

실행 중 `.sqlite` 한 파일만 복사하면 WAL의 최신 커밋이 빠질 수 있다. 간단한 데모 백업은 서비스를 정상 종료한 뒤 `/data`를 복사한다. 실행 중 백업이 필요하면 SQLite의 일관된 backup 절차를 별도로 사용한다. 배포 때 볼륨을 삭제하는 명령은 데이터 삭제다.

## 검증

`test/persistence.test.mjs`는 실제 임시 SQLite 파일과 HTTP/WS 클라이언트를 사용한다.

- 서버 새 인스턴스: 같은 방·승인·재고·적 HP·획득 원장·WS/world 영수증 복원.
- 복원 직후: P/UX/foreground/연결이 허용 상태로 살아나지 않음, 새 보고·명시 재개 필요.
- 저장 실패 주입: claim 503·health 503, 성공 방송 없음, 다음 정상 부팅에서 실패한 지급 없음.
- 실제 자식 Node 프로세스의 SIGKILL 후 새 프로세스: 이미 ACK한 수집과 중복 방지 유지.
- DB 파일/WAL에 원문 세션 토큰과 시험 폰 좌표가 들어가지 않음을 확인.

프로세스 강제 종료 시험은 실물 저장장치 전원 차단 시험과 다르다. 실차·실물 GPS·운영 계정 인증 검증까지 포함하지 않는다.
