# 전기 도둑

충전 중인 차 안에서 가족 2~4명이 하는 숨은 도둑 찾기 게임. 마피아류 게임처럼 비밀 역할·토론·투표로 진행한다. 폰은 웹으로 들어온다. 서버 계약(`server/openapi.json`·`protocol.json`)과 무관한 독립 폴더다.

## 왜 차와 폰이 다 필요한가

| 기기 | 맡는 일 |
| --- | --- |
| 폰 | 비밀 역할·손패·단서. 옆 사람이 보면 게임이 안 된다 |
| Pleos 앱 | 누가 뭘 냈는지 숨긴 채 합계만 내는 심판. 실제 배터리로 사건을 터뜨리고, 정전과 도둑의 조작을 차 실내에 적용한다 |
| 같은 차 안 | 얼굴을 보고 말로 추리한다 |

## 규칙

1. QR로 들어오면 한 명이 몰래 도둑이 된다(운전자일 수도 있다). 시작하면 규칙 화면이 나오고, 역할과 할 일은 폰에서 꾹 누르는 동안만 보인다. 모두 "이해했어요"를 누르면(또는 진행자가 "바로 시작"을 누르면) 게임이 시작된다. 폰에서 규칙을 다시 볼 수 있다.
2. 판을 시작할 때 덱(−1~+4, 큰 카드는 적게)을 섞어 **각자 4장**을 받는다. 도둑도 같은 덱에서 받는다. 사건마다 1장 내고, 다음 사건 전에 1장 뽑는다. 손패는 충전·토론 중에도 폰에서 볼 수 있다.
3. **배터리가 5% 오를 때마다 사건**이 터진다(최대 6번). 차 화면에 **구간**(예: 7~9)이 뜬다. 구간은 지금 손패로 맞출 수 있는 합계 중에서 고르되, 너무 작은 합계와 "모두 가장 큰 카드"는 피한다.
4. 각자 폰으로 카드 한 장을 몰래 내고, **살펴볼 사람**을 한 명 고른다.
   - 살펴본 사람의 카드가 50% 확률로 보인다("민지는 이번에 +2를 냈어요"). 본인만 보고, 말할 때 거짓말해도 된다.
   - 도둑 폰에만 **몰래 장난**이 뜬다: 조명 빨갛게 / 바람 훅 / 안 해요.
   - 메시지: `{type:'play', card, watch: 플레이어id|null, prank: 'NONE'|'LIGHT'|'WIND'}`. 2명 판은 watch를 보내지 않는다.
5. 차는 **합계만** 공개한다.
   - 구간보다 모자라면 **정전**: 무드등이 꺼지고 바람이 가장 약해지며 퓨즈가 하나 나간다.
   - 구간을 넘치면 **과부하**: 무드등이 빨개지고 바람이 몇 초 세게 불며 퓨즈가 하나 나간다.
   - 도둑은 따로 마이너스 카드가 없다. 일부러 크게 또는 작게 내서 구간 밖으로 밀어낸다. 실수인지 고의인지가 추리거리다.
6. 결과 화면(15초)에서 운전석 차 화면의 **비상 차단기**로 방금 난 정전·과부하를 취소할 수 있다(3~4명은 한 판에 2번, 2명은 1번). 퓨즈와 실내가 되돌아간다. 메시지: `{type:'breaker'}`(차 화면만).
7. 토론(60초) 뒤 비밀 투표(20초). 과반이 지목하면 체포한다. 도둑이면 가족 승리, 억울한 사람이면 퓨즈가 하나 나간다.
8. 퓨즈 3개가 다 나가거나 사건이 끝날 때까지 못 잡으면 도둑 승리.

2명이면 도둑 없이 차가 매 사건 몰래 −2~+2를 더한다(결과 때 공개). 토론·투표 없이 사건을 모두 버티면 승리, 퓨즈 3개가 나가면 차의 승리다.

## 실행

```sh
npm install
npm start          # 8210 포트. 같은 Wi-Fi 폰이 들어올 주소로 QR을 만든다
npm test
```

- 큰 화면: `http://localhost:8210/`
- 폰: QR 촬영, 또는 `/p`에서 방 코드 입력
- QR 주소 고정: `PUBLIC_ORIGIN=https://example.test npm start`

## Pleos 앱

Z-RIDE 게임 허브 `android/pleoshub`(`ai.zride.hub`)가 차량 쪽 앱이다. 허브 목록에서 "전기 도둑"을 고르면 큰 화면 웹 페이지를 WebView로 띄우고, 페이지는 공통 SDK `/zride-car.js`(`games/sdk`)로 차와 이어진다. 연동 규칙은 [연동 가이드](../sdk/README.md)를 본다. 차 없이 개발할 때는 `http://localhost:8210/?mockcar`.

- 차 → 게임: Pleos `EvBattery`의 실제 SOC와 표준 AAOS의 UX 제한·기어를 페이지로 넘긴다. 페이지가 `{ "type": "soc", "value": 42, "source": "CAR" }`를 서버로 보내고, 이때부터 시연 충전은 멈춘다.
- 게임 → 차: 상태의 `cabin`(`light`: `NORMAL`·`RED`·`OFF`, `air`: `NORMAL`·`LOW`·`GUST`)을 받아 무드등과 바람세기를 바꾼다. 설정 온도는 바꾸지 않는다(몇 초 바꿔서는 체감이 안 되고 충전 중 전력만 더 쓴다).
- 바람은 공조가 켜져 있을 때만 바꾼다. `LOW`는 가장 약하게(1단), `GUST`는 가장 세게 4초 불고 원래 세기로 돌아간다. 원래 바람세기·오토 상태를 저장했다가 되돌린다.
- 주차·UX 허용·화면 표시 중일 때만 적용한다. D단이면 페이지가 게임을 가리고 앱이 바로 원래 값으로 되돌린다. Pleos도 앱 화면을 시스템 차단 화면으로 덮는다.
- 원래 값은 게임이 차를 건드리기 전까지 2초마다 다시 읽어, 사용자가 바꾼 조명·바람을 따라간다. 처음 바꾸는 순간 기기에 저장해 두어, 게임 중 앱이 죽어도 다음 실행 때 되돌린다.
- 공조가 꺼져 있으면 바람을 건드리지 않는다. 못 읽은 좌석도 건드리지 않고, 게임 중에도 읽히는 대로 채운다.
- 게임 서버에 못 붙으면 "게임 서버에 연결할 수 없어요" 화면을 띄우고 5초마다(또는 버튼으로) 다시 붙는다. 첫 차량 신호 전에는 "차량 상태를 확인하는 중…"으로 가린다.
- 권한은 `pleos.car.permission.CONTROL_CAR_LIGHTS`·`CONTROL_CAR_CLIMATE`(에뮬레이터에서 normal). 무드등 색은 RGB 값이다.
- SDK 호출은 서비스가 붙을 때까지 멈출 수 있어 별도 스레드에서 부른다. 에뮬레이터 GPU에서는 WebView를 소프트웨어 렌더링으로 그린다.

```sh
cd android && ./gradlew :pleoshub:assembleDebug
adb install -r pleoshub/build/outputs/apk/debug/pleoshub-debug.apk
adb shell am start -n ai.zride.hub/.HubActivity --es game electric-thief
adb forward tcp:8088 tcp:8088   # Virtual Console: http://127.0.0.1:8088/ 에서 배터리·기어 조작
```

서버를 끌 때 `lsof -ti tcp:8210 | xargs kill`을 쓰지 않는다. 에뮬레이터도 그 포트에 붙어 있어 같이 꺼진다.

## 아직 안 된 것

- 실차 시험. 에뮬레이터에서만 확인했고, 실차·배포 앱의 제어 권한 허용 여부는 미확인이다.
- 게임 서버 배포. 앱의 기본 주소는 에뮬레이터용이고, Release는 HTTPS 주소가 필요하다.
- 실제 가족 플레이 시험. 카드 수치·목표·시간은 추정값이다.
- 실물 아이폰 시험.
