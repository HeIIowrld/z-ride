# 스케치 스타일 리디자인 — 지시서 (Codex용)

첨부 이미지 2장(design/sketch_polejump.png, design/sketch_raindrop.png)은 사용자가 그린 화면 스케치다. 두 게임(폴짝 전봇대, 빗방울 캐치)과 허브를 **브라우저 오프라인 공룡 미니게임처럼 단순한 흑백 라인 드로잉 + 손그림 스케치 느낌**으로 바꾼다. 게임 규칙·로직·공통 모듈 API·기록 형식은 그대로 두고, 화면 구성과 그림만 바꾼다. (해당 미니게임의 캐릭터·에셋을 따라 그리지 말고, 분위기만 참고: 흰 바탕, 검은 선, 색 없음, 픽셀/선 위주 단순 도형.)

## 공통 비주얼 규칙
- 색: 흰 배경(#fff 또는 아주 옅은 종이색 #fafaf7) + 검정/회색 선만. 그라데이션·그림자·컬러 금지. 경고(과속 등)도 검정 반전 깜빡임이나 굵은 테두리로 표현.
- 선: 손그림 느낌. 직선도 살짝 흔들리게 그리는 `sketchLine(ctx,x1,y1,x2,y2,{jitter})` 유틸을 shared/sketch.js에 만들어 두 게임이 같이 쓴다(시드 고정해서 프레임마다 떨리지 않게, 또는 아주 약하게만 떨리게). 해칭(빗금) 채우기 유틸 `hatchRect(...)`, 손글씨 느낌 텍스트는 시스템 폰트 + 약간 회전 정도로.
- UI(HTML 부분: 헤더, 버튼, 모달, 결과 화면, 허브 카드)도 흑백. 테두리 2px 검정, 모서리 살짝 둥글게, 버튼은 흰 바탕 검은 테두리, 누르면 반전. 폰트는 시스템 sans 또는 monospace.
- 세로(portrait) 화면 기준. 폰 전체 높이를 쓰는 레이아웃.

## 공통 레이아웃 (두 스케치 공통)
위에서 아래로:
1. **창밖 뷰 (화면 위쪽 약 60%)**: 차 안에서 옆 창문을 보는 시점. 상단과 오른쪽에 차 지붕/A필러/사이드미러 윤곽선(스케치처럼 굵은 곡선, 지붕 쪽은 빗금 해칭). 그 안이 게임 플레이 영역.
2. **창틀/도어 라인**: 뷰 아래에 가로선 2~3줄(창틀, 도어 벨트라인), 오른쪽에 작은 도어 손잡이 윤곽.
3. **하단 HUD 패널 (화면 아래쪽)**: 세 칸, 손글씨 라벨.
   - **얻은 아이템**: 동그라미 슬롯 3개. 얻은 아이템(부품·냉각수 셀 등)을 단순 아이콘으로 표시, 개수 숫자.
   - **이벤트**: 네모 칸 안에 현재 이벤트 칩들(동그라미 안 글자). 예: 폴짝 전봇대는 "장애물", "새", "과속!" / 빗방울 캐치는 "이슬비/굵은 비/폭우", "실시간 비바람(진짜 비 모드)" 등. 해당 없으면 "-".
   - **시속**: 네모 칸에 현재 km/h 큰 숫자, 아래 작게 "제한 60"(없으면 "제한 —").
   - 점수·콤보는 뷰 왼쪽 위에 작은 손글씨 숫자로(공룡 미니게임처럼 우상단 숫자 스타일도 OK).
- dev 패널은 기존처럼 접이식, 흑백 스타일.

## 폴짝 전봇대 (sketch_polejump.png)
- **세로 화면으로 전환.** 창밖 뷰 안에 전봇대(세로 두 줄 선)가 흘러감. 기둥 높이 라인 1·2·3번을 기둥에 짧은 가로 눈금으로 표시(스케치의 빨간선은 설명용이므로 화면엔 아주 옅은 점선 가이드 정도만, 또는 생략 가능).
- 캐릭터: 손가락 닌자를 단순 라인 드로잉으로(손가락 실루엣 + 머리띠 선 하나). 이모지·컬러 사용 금지.
- 장애물: 스케치처럼 **팔각형 "STOP" 표지판**, **빗금 친 네모 상자(전단지/변압기)**, 까치집(얽힌 선 덩어리), 새(V자 두 획) — 모두 라인 드로잉.
- 배경: 바닥 지평선 한 줄 + 가끔 지나가는 낮은 덤불/풀 점선(공룡 미니게임 바닥처럼), 하늘엔 아무것도 없거나 가끔 구름 윤곽선.
- 스크롤 방향 규칙(좌석)과 게임 규칙은 그대로.

## 빗방울 캐치 (sketch_raindrop.png)
- 스케치의 파란 손글씨 메모가 물방울 동작 설명이다. 그대로 반영:
  1. **"비에 의해 빗방울이 묻음"**: 빗방울이 유리 전체에 점점이 달라붙는다. 모양은 스케치처럼 제각각인 작은 획 — 점(·), 짧은 대시(-), 작은 c/u/ʊ 모양 곡선, 쉼표 모양. 한 가지 원으로 통일하지 말고 이 4~5가지 글리프를 랜덤으로(크기·회전 랜덤) 찍는다.
  2. **"무게에 의해 내려오다가 빗방울과 만나 커짐"**: 무거워진 방울이 아래로 흘러내리다 경로의 다른 방울과 만나 흡수하며 커진다. 커진 방울은 동그라미 윤곽 + 아래쪽 꼬리(눈물 모양)로 그리고, 지나간 자리에 가는 선 자국.
  3. **"풍속, 시속에 의한 빗변이동"**: 흘러내리는 방향은 수직이 아니라 비스듬한 빗변 방향. 각도 = 중력 + 차 속도(시속) + **풍속**의 합성. 풍속은 vehicle feed에 `windKmh`(없으면 0)로 받고, dev 패널에 "풍속" 슬라이더(-30~30, 음수는 반대 방향) 추가. 정차·무풍이면 거의 수직.
  - 스케치 왼쪽 아래 창틀 위의 손 = 받침.
- 흘러내리는 방울은 지나간 자리에 가는 회색 선 자국.
- 받침: 스케치처럼 **창틀 바로 위에 있는 손(손바닥을 위로 펼친 손) 라인 드로잉**을 좌우로 움직임. 기존 컵 캐릭터 대체.
- 창틀 물받이 게이지: 창틀 가로선 사이를 빗금으로 채워 차오르는 표현.
- 흐름 각도(차 속도·좌석) 규칙과 게임 규칙은 그대로.

### 빗방울 캐치 게임성 튜닝 (필수, 현재 버그)
브라우저 테스트 결과: 방울은 생성되지만(2.5초에 약 6개) 20초가 지나도 ~50개 작은 방울이 붙어만 있고 하나도 합쳐져 흘러내리지 않음 → 점수 0, 게이지 0, 게임이 진행되지 않음. 고칠 것:
- 이슬비(처음 30초, 빗발 1배)에서도 3~5초 안에 첫 방울이 흘러내리고, 이후 1~2초마다 하나 정도 흘러내리게. 단계가 오를수록 더 많이.
- 방법 예: 생성 반지름 범위 확대, 새 빗방울이 기존 방울 위에 떨어지면 흡수해 키우기, R_SLIDE 낮추기, 거리 < r1+r2+여유 이면 합치기, 흘러내리는 방울이 경로의 방울 흡수.
- 아무것도 안 하면 놓친 물로 게이지가 차서 60~120초 안에 넘쳐 게임오버.
- window.__raindrop.getState()에 stuck, sliding, caught, missed, elapsedMs 추가.
