# 빗방울 캐치 — 구현 지시서 (Codex용)

기존 코드(SPEC.md로 만든 허브·shared/·games/pole-jump)를 먼저 읽고, 같은 스타일·구조로 이어서 만든다. 규칙은 SPEC.md와 동일: 빌드 도구·외부 라이브러리 없음, Canvas 2D, 한국어 UI, localStorage는 try/catch, 기존 기능을 깨지 말 것.

## A. 공통 기반 변경
1. **shared/passenger.js (신규)**: `ensurePassenger()` → 첫 실행 시 "동승자입니다 (운전 중인 사람은 플레이하지 마세요)" 확인 모달, 확인 전엔 게임 시작 불가. localStorage 'zride.passengerConfirmed'. **폴짝 전봇대에도 적용.**
2. **shared/vehicle.js**: update payload에 `wiper: { on:boolean, level:0~3 } | null` 추가.
   - 서버 WS `/vehicle`에서 `{type:'wiper', on, level}` 수신 (주석: 차량 앱이 Pleos Vehicle registerWiperState() 값을 서버로 중계. 사무국 확인 전이라 없을 수 있음).
   - 받은 적 없으면 null. 게임은 null이어도 끝까지 동작해야 함.
   - dev 모드 패널에 게임이 추가 슬라이더를 붙일 수 있게 `addDevControl({label,min,max,step,value,onInput})` 같은 확장 함수 제공(이미 비슷한 게 있으면 재사용). 와이퍼 슬라이더(0=꺼짐, 1~3)는 vehicle.js 공통 패널에 넣어 wiper 값으로 내보냄.
3. **shared/inventory.js**: ITEMS에 `coolant: {name:'냉각수 셀', type:'material'}` 추가.
4. **shared/records.js**: 변경 없음. 모드 구분은 `stats.mode: 'real'|'practice'`로 저장하고, `getBest(gameId, filterFn?)` 처럼 필터를 받을 수 있게 확장(기존 호출 호환).
5. **허브**: 게임 카드에 빗방울 캐치 추가, 최고 기록은 진짜 비/연습 따로 표시.
6. **README**: 새 게임, wiper 메시지 형식, 라이선스 섹션("외부 에셋·라이브러리 없음, 모든 그래픽·소리 코드로 생성") 추가.

## B. 게임: 빗방울 캐치 (games/raindrop, gameId 'raindrop')
### 화면 (세로)
- 차 옆 창문을 안에서 본 화면. 둥근 창틀, 유리 뒤 흐릿한 바깥(그라데이션 + 흐릿한 원형 불빛/나무 실루엣이 차 속도에 맞춰 천천히 흐름).
- 아래쪽 창틀 안에 **물받이 게이지**(놓친 물이 차오름).
- 창틀 바로 위를 좌우로 움직이는 **받침**: 오리지널 캐릭터 "물방울 컵"(작은 컵 + 눈 두 개, 단순 도형).
- 빗방울: 반투명 원(가장자리 밝은 하이라이트 + 아래쪽 그림자로 굴절 느낌), 흐른 자리에 서서히 사라지는 물자국 선.
- HUD: 점수, 콤보, 냉각수 셀 수, 모드 배지("진짜 비 모드 🌧" / "맑은 날 연습 모드"), 현재 빗발 단계(이슬비/굵은 비/폭우).

### 빗방울 물리 (간단한 파티클)
- 각 방울: x, y, r, state('stuck'|'sliding'), vx, vy.
- 생성: 빗발 세기에 따라 초당 N개, 유리 위 랜덤 위치에 작은 r(2~5px)로 부착.
- 합치기: 두 방울이 겹치면 면적 보존으로 하나로 합침(r = sqrt(r1²+r2²)), 위치는 면적 가중 평균.
- 흘러내림: r ≥ R_SLIDE(약 9px)면 sliding. 속도 크기는 r에 비례해 증가. 흐르면서 경로상의 stuck 방울 흡수.
- 흐름 방향(각도): 중력 방향(아래) + 차 속도에 의한 뒤쪽 성분 합성.
  - `back = min(speedKmh / 120, 1.2)` 정도, 방향벡터 = normalize(dir*back, 1). 정차 시 거의 수직, 고속이면 거의 옆.
  - dir: seat='right' → +1(오른쪽으로), 'left' → -1. (SPEC.md의 seat 사용)
  - 속도 변화는 지수 평활로 부드럽게.
- 튀는 방울: 30초 이후 빗방울 생성 시 확률적으로 작은 방울 3~5개를 주변으로 흩뿌림(짧은 이동 후 부착).
- 화면 좌우 밖으로 나간 방울은 "흘러나감"으로 처리하되 게이지에는 절반만 반영(옆 창틀로 흘렀다고 간주).

### 조작
- 드래그(터치·마우스) 좌우 = 받침 이동(손가락 x를 따라가되 약간의 이징). 키보드 ←/→ 도 지원(dev 테스트용).
- 탭 = 탭 위치 근처(반경 30px)의 stuck 방울을 sliding으로 전환(톡 떨어뜨리기). 받침 위 탭은 드래그로 처리.

### 점수·실패
- 방울이 받침 상단 영역에 닿으면 받음. 점수 = clamp(round(r 기반 1~20)) (작은 방울 1점, 큰 방울 20점).
- 콤보: 연속으로 놓치지 않으면 증가, 배수 = 1 + floor(combo/5)*0.5 (최대 3배). 놓치면 리셋.
- 차 속도는 점수에 영향 없음.
- 놓친 방울(창틀 바닥에 닿음)은 r² 비례로 게이지 증가. 게이지 100% → 게임오버(창틀 넘치는 연출).
- 받은 방울 중 15점 이상 5개마다 inventory.addItem('coolant',1,{from:'raindrop'}) + "+1 냉각수 셀" 팝업.

### 빗발 단계
- 기본 시간 진행: 0~30초 이슬비(생성 적음, 느림, 튀는 방울 없음) → 30~90초 굵은 비(생성↑, 합쳐짐↑, 튀는 방울) → 90초~ 폭우(생성 많음, 흐름 속도↑).
- 실제 강도 반영: wiper.on이면 "진짜 비 모드". 생성률 = 시간단계 기본값 × (1 + 0.3 × wiper.level).
- dev 패널 게임 전용 슬라이더 "빗발 세기"(0.5~3배)로 생성률 배수 직접 조절.

### 모드
- 시작 시점에 wiper?.on === true → mode 'real', 아니면 'practice'. 플레이 중에는 바뀌지 않음(배지 표시만 갱신 안 함).
- wiper가 null이면 "와이퍼 정보 없음 — 연습 모드" 안내.

### 결과·기록
- 결과 화면: 점수, 받은 방울 수, 가장 큰 방울(점수), 최고 콤보, 시간, 냉각수 셀, 모드, 해당 모드 최고 기록 여부, 다시하기/허브.
- records.saveRecord({gameId:'raindrop', score, durationMs, distanceM, stats:{mode, caught, biggest, maxCombo, coolant}, endReason:'overflow'}).
- 진짜 비 모드 최고 기록 갱신 시 localStorage 'zride.skins'에 'cup_rainbow' 추가(결과 화면 표시만).

### 기타
- 정차 여부와 무관하게 플레이 가능(일시정지 없음).
- WebAudio 합성음: 받음(크기에 따라 음높이), 놓침, 넘침. 음소거 버튼(기존과 같은 방식).
- devicePixelRatio, 리사이즈, requestAnimationFrame 대응. 방울 수 상한(예: 250)으로 성능 유지.
- `games/raindrop/index.html?dev=1`에서 차 속도·와이퍼·빗발 세기 슬라이더 + 마우스/키보드로 전부 테스트 가능해야 함.

## C. 완료 조건
- 콘솔 에러 없음. dev 모드에서: 방울 부착→합쳐짐→흘러내림, 속도 올리면 비스듬히 흐름, 받기·점수·콤보, 놓치면 게이지 증가→게임오버→기록 저장(mode 포함). 와이퍼 슬라이더 1 이상으로 시작하면 진짜 비 모드.
- 폴짝 전봇대도 여전히 동작하고, 두 게임 모두 동승자 확인 모달이 뜸.
- 마지막에 바뀐/새 파일 목록을 짧게 출력.
